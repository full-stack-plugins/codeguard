# CodeGuard 单能力验收记录模板

> 日期：2026-10-07。用途：接手模型复制后填写真实结果。模板本身不是运行证据，不新增验收要求；沿用现有 OpenSpec 与交接手册。

## 1. 身份与范围

| 字段 | 必须填写的内容 |
|---|---|
| OpenSpec | 原任务 ID、具体 requirement/scenario、规格路径 |
| 被验收单元 | canonical 语言 / 构建生态 / syntax、documentation、conventions 或 vulnerabilities |
| 输入范围 | 源集、模块、版本、方言、features/targets、排除和未解析条件 |
| 候选身份 | commit、dirty 文件摘要、可执行程序摘要、实际包版本 |
| 执行环境 | OS/架构、宿主版本、工具版本/摘要、配置/规则/锁/数据库身份 |
| 对应实现 | 修改文件与复用入口；不得用文件存在代替行为实现 |

同一构建根的四项能力分别记录。共享工具可以复用执行证据，但必须分别证明规则和范围；一个语言的证据不能代替另一语言资格。

## 3. 四类专属证据

| 类别 | 必需记录 |
|---|---|
| syntax | grammar来源/许可/ABI/摘要、ERROR/MISSING与不可定位恢复、原生优先路由、项目版本/源集、合法新版语法与独立原生对照 |
| documentation | 用途/参数/返回/异常详细说明、空与占位说明、继承/生成代码/重载/宏、原配置实际启用；模糊语义不能伪高置信规则 |
| conventions | 原生工具与实际加载规则集合、有效配置来源、预置违反规则与合法反例；格式化或build成功不代替规范检查 |
| vulnerabilities | 解析依赖图/直接传递/条件依赖、advisory与库来源及时效、真实漏洞和修复版本、模糊匹配与离线失败、复检原工具 |

## 4. 修复闭环与宿主

按同一问题身份依次保存：首次发现 → 重复扫描同任务 → next指引 → 修复 → task verify → 完整且受信关闭或具体未完成 → 再引入问题 → 原父链重开。

还要测试：删Markdown不删事实、手工勾选不关闭、连续无进展受预算限制、环境故障任务不引导乱改源码、未经批准消失保持开放。精确白名单保留原始问题，批准/失配/到期/撤销单独记录。

CLI测试、真实插件宿主触发、发行包实装分开填结果。宿主证据必须包含触发事件、实际调用、反馈到对话、重复触发去重和失败可见性；仅CLI输出不能记为宿主验收。

## 5. 精度、覆盖与性能

按语言/类别/工具版本/来源组保留样本量、TP/FP/FN/TN、unknown/pending、precision/recall及区间；分母能从逐样本原始记录重算。开发回归和独立holdout不可合并成独立验证。没有发现时precision不可估计；未知不能转TN；白名单前原始结果不能删除。

阈值沿用正式规格：确定性必备零假通过/零工具故障误判，预置真问题全检出，关键安全/CVE回归零漏报，足够裁定样本的adapter/category precision的95% Wilson下界至少0.98。样本不足仍不足，不能全局平均代替。性能记录同覆盖冷/热p50/p95、内存、缓存失效和取消回收；未冻结基线不得编造性能达标。
