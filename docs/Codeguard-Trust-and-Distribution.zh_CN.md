## 1. 四类输入与独立权威

项目原生配置决定本轮检查语义；运行参数只控制预算；策略/rulepack/tool-lock 候选描述待验证要求；批准来自受保护宿主或 CI 的独立上下文。摘要一致只证明字节绑定，本地 approved 字段、环境变量或智能体转述不是批准来源。扫描不自动安装，不执行配置字符串作为 Shell。

当前 `config validate/explain --policy-candidate FILE` 只检查候选结构、锁摘要、非空义务及精确排除声明，`effective_policy=null`。排除必须是精确文件/内容摘要、结构化原因与有限期限，不能通配；排除发生在扫描前，误报处置发生在保留原生 finding 后。二者不能互相替代。

rulepack 目标布局为 `rulepacks/<pack-id>/<version>/{manifest.json,rules.json,tool-configs/,compatibility.json,fixtures/}`，记录来源、许可证、摘要、兼容、严重度与语义迁移。当前候选目录不代表完整发行规则包。

## 2. 批准快照与修订链

批准快照协议 `approval-snapshot:1.0` 记录策略修订、最长有效期及每个已批准候选的 ID/原始字节 SHA-256。Rust 的 `bind_candidate_to_snapshot` 先比对快照的预期 SHA-256，再校验候选是否在快照中、修订及有效期是否一致，并与调用方提供的本次原生 finding 身份精确匹配。更改候选中的批准文字、评审人或任何字段都会改变摘要；同次 PR 新增候选若不在此前快照中不能命中。此函数的 `BoundToPinnedSnapshot` **仅证明输入之间的绑定**，不证明摘要、时钟或 finding 来自受保护来源；项目可写配置或智能体自行计算的摘要不能升级为授权。正式门禁还须由隔离的 CI/宿主固定旧策略快照、可信时钟和真实原生发现。

快照 `1.1` 增加必填 `revoked_decision_ids`，由同一策略修订同时固定有效候选与撤销 ID。绑定函数在解析并核对快照摘要后优先返回 `Revoked`，即使旧候选字节仍列在 `decisions` 中也不能沿用；重复、通配撤销 ID 或 `1.1` 缺撤销集合使整份快照无效。旧 `1.0` 快照仍可读取，但不能包含撤销字段。当前这只是快照内的撤销表达与字节绑定，还没有可信发布、修订链事件、真实 finding 门禁或 `explain` 自动发现，不能把本地构造的 `1.1` 快照当成批准。

替代候选使用决策协议 `1.1`，必须以 `replaces_decision_id` 引用不同的旧决策 ID；普通 `1.0` 候选不得携带该字段。替代候选绑定时，同次快照必须撤销旧 ID；还要提供旧决策字节，确认稳定 finding、检查器、规则、类别和精确目标归属没有扩大。仅调用普通绑定接口、缺旧决策、引用错 ID 或改到另一目标，均不能得到替代绑定结果。该结构核对仍不能证明旧字节来自先前可信批准；受保护策略发布需继续验证旧决策存在、旧快照来源及修订链无环。

前序绑定接口进一步要求旧决策字节在**另一份**固定摘要的前序快照中列明且尚未撤销，旧决策声明的修订与该快照一致；前后快照修订不能相同。缺前序摘要、摘要与字节不符、旧字节被改或前序快照已撤销旧决策均拒绝。两个摘要的真正来源和修订先后顺序不能由工作区文件自证，必须由受保护发布流程固定；该接口的成功值仍不是白名单生效或交付授权。

多次纠错使用按“当前候选的直接前驱 → 最初普通候选”排列的前序链。Rust 逐跳核对旧决策确在对应快照、同一 finding/精确目标、子快照撤销其前驱、各跳策略修订不同且旧决策有效期不超过当时上限；必须走到不再替代别人的根候选。截断、乱序、多余节点、重复决策 ID/修订形成的环或超过 32 跳均拒绝。结构完整仍不证明快照来自可信发布，也不能用版本字符串推断修订发生的真实先后。

## 3. 签名、Git 基线与最终门禁

签名精确绑定原始 UTF-8 载荷，消息域、NUL、密钥 ID、NUL、载荷字节组成验签输入，不在验签前后重新序列化 JSON。当前使用 ring 的 Ed25519 基础；绑定工作区、策略修订、基线、序号、期限和快照摘要。

**当前局部签名能力：**

Rust 现可在宿主预固定公钥、时钟和基线上核验 Ed25519 签名，精确绑定工作区、策略修订、基线提交、防回滚序号、有限期限和批准快照原始字节。普通候选桥接先核验签名，再核对快照内修订与签名修订一致，随后沿用精确候选身份与字节绑定。改签名原文、换目标/快照/私钥、过期、撤销、缺可信时钟或回滚均拒绝。项目没有自选公钥或签发批准的 CLI；公钥可信来源、撤销及最低序号仍由受保护宿主负责，尚未接通真实宿主门禁；多跳修订链基础见下文。签名成功不能把原生 incomplete 转为通过。

当前多跳签名入口会逐跳核验历史签名和快照字节，再检查工作区、序号、签发/审核先后与当时有效期；历史 pin 由验签结果生成，不接受项目自行提供。随后继续原有精确替代/撤销/无环校验。历史条目今天过期不抹去当时合法记录，但宿主当前撤销的公钥仍拒绝绑定。历史时间和公钥来源及实际门禁仍须由受保护宿主接入；代码基线祖先关系由下述 Git 联合入口验证。以上局部签名核验补充了前文的实施状态；候选查询与纠错命令仍无批准或放行效力。

Git 联合入口现进一步核对每跳已签名基线的原生祖先关系（允许同一提交），签名有效但代码历史无关仍拒绝。缺对象、浅历史、旧 Git 不支持禁取对象参数、取消或预算耗尽均为未完成；不降级为纯签名通过。工具和仓库可信来源、批准发布及最终门禁仍待宿主接线，不赋予本地候选授权。

领域门禁现进一步核对白名单身份与原生 finding：宿主冻结 checker/tool/category/obligation 映射，第一处定位作为主目标，源码核对路径，依赖核对组件与显式版本。缺定位、错主目标、错工具或缺/冲突映射均保留活动阻断；次要定位不能扩展豁免。全部处置应用前先识别重复 finding 和复用的决策 ID，冲突双方不留下先到的白名单状态。此增量不证明原生制品摘要、批准来源或依赖图归属，也未接通真实宿主门禁。

领域 finding 还增加本轮完整原生身份绑定。只有它与批准项附带的观察身份逐字段一致，才可能进入白名单处置；旧报告缺身份、文件字节或指纹变化、工具/适配器/rulepack 摘要变化、依赖图或 advisory 变化都会保留原始及活动阻断并返回未完成。这个字段只是领域输入契约，不能让项目自行填写并取得可信来源；正式宿主仍须从本轮原工具结果和真实目标字节复核后冻结它。

应用处置时还必须采用最终门禁的可信时钟：到期边界不包含，缺最终时钟、零值或早于取证时间均不应用白名单，不能重放旧 observed_at 维持豁免。普通无白名单门禁不因缺此新字段改变结论。已验签快照现提供只读到期上限，宿主固定当前批准相关约束的最早边界；历史批准按当时审核时间核验，不将历史到期时间套到当前合法替代条目。可信时钟和真实批准生产仍由宿主接线。

门禁现还与宿主独立冻结的当前策略修订比较，处置不得用自己声明的修订充当当前策略。签名入口可生成不可从项目 JSON 反序列化的只读处置绑定预览，固定候选/快照字节、范围、身份和最早期限；替代入口先核验完整签名与 Git 链。预览的独立批准标记始终 false，不增加自批命令或放行能力；来源核验、真实宿主批准和发布仍未接通。

**最终范围绑定：**

签名预览中的 `approval_scope` 保留已核验的工作区及当前批准上下文基线。门禁须与宿主独立冻结的范围精确比较，不得从处置字段复制宿主范围。缺范围、跨工作区、错基线或非法身份均不应用白名单并保留活动阻断。基线仅接受完整非零、小写 SHA-1/SHA-256 提交 ID；它是批准上下文的基线，不是临时工作树 HEAD。旧输入仍可读取，未带范围的旧白名单不能放行；没有白名单的普通判定保持原语义。来源可信性和真实宿主接线仍待实施。

## 4. 工具包核验、布局与发布

| 阶段 | 已有基础能力与不变量 | 仍需接线 |
|---|---|---|
| 静态库存/verify | 显式候选锁、入口/运行时/目录摘要及权限，未批准保持 matched_untrusted | 可信完整必需库存 |
| install preview | 清单/锁及完整布局声明绑定，内容核验 not_run；apply 写前阻塞 | 正式授权 apply、恢复及运行时管理 |
| HTTPS 传输 | 固定 URL/大小/SHA-256/重定向 authority、TLS、有界字节、同 deadline/cancel；不继承代理/自动解压或重试 | 真实宿主网络与来源授权 |
| ZIP/tar.gz | 先核验所有成员，拒绝链接/逃逸/sparse；受控 GNU/PAX 路径与长度，保留空目录 | 各发行格式/平台矩阵 |
| bundle 与完整布局 | bundle-tree-v1 与本机算法比对；按目录边界投影根，保留未消费成员；清单 1.2 install_tree_sha256 | 安装目的地/运行时恢复 |
| raw 发布 | 有界冻结字节与锁定 binary-sha256.bin 定位；私有暂存、固定目录 FD、不覆盖发布、再次复核 | 正式 CLI 服务编排 |
| 目录发布 | macOS/Linux 私有暂存和不覆盖重命名；复用前核对全树成员/权限/类型 | Windows 等价能力 |
| 发行签名 | 独立 distribution.v1 域，清单/锁/发行者/通道/平台/序号/期限绑定；显式离线/网络发布服务 | 真实公钥/撤销/时钟及公开安装接入 |

网络发布先校验签名与精确站点许可，下载和发布共享预算；不能从本地 URL+自算摘要产生批准。各阶段收据只描述自己完成的工作，不代替完整安装或质量通过。已有损坏、链接、FIFO、异常权限目标不覆盖；取消清理本次暂存，发布后失败可能保留完整制品，重试须复核。普通同权限本地执行不承诺对抗恶意同用户写入。

源码依据：[签名批准](../crates/codeguard-cli/src/signed_approval_verifier.rs)、[发行清单](../crates/codeguard-cli/src/distribution_manifest.rs)、[运行时](../crates/codeguard-runtime/src)。验收：[HTTPS](../tests/acceptance/package-https-transport.md)、[布局](../tests/acceptance/distribution-layout-binding.md)、[签名发布](../tests/acceptance/signed-package-publication.md)、[网络发布](../tests/acceptance/signed-network-publication.md)。测试密钥不是发行信任锚。

## 5. npm、WASM 资产与回滚

npm 已发布 macOS arm64 0.1.0；Node 只转发到打包的 Rust 二进制，无检测或解析逻辑，无安装生命周期脚本。默认本地 private 打包与显式 public 模式分开。当前缺不可变源码/tag 绑定，多平台支持不能由打包器分支或交叉编译推断。使用方式归 [README](../README.zh-CN.md#npm-安装与一次性调用)。

目前已有[候选资产清单](../grammars/manifest.json)及固定提交的 Java、Python、TypeScript、TSX WASM，保留 CodeGraph 和上游 MIT 许可证；[Rust 校验器](../crates/codeguard-adapters/src/grammar_asset_manifest.rs)核对来源字段和原始字节。四份资产的 Rust 离线加载及基本解析测试已通过；语言版本、方言、完整语料、完整调度和 MSRV 实编仍未验收，所以资产仍标记为 `candidate_unvalidated`。详见[局部验收](../tests/acceptance/grammar-asset-candidates.md)、[Python 资产验收](../tests/acceptance/python-grammar-asset-candidate.md)和 [TSX 纠错验收](../tests/acceptance/tsx-grammar-candidate.md)。可选源码构建仅有 Java/TypeScript/TSX 的局部单文件兜底，Python 尚无 CLI 路由；公开 npm 包仍不含这些字节或检查路径。

CodeGraph 使用 JavaScript `web-tree-sitter` 加载 grammar WASM，初始 ABI 观察也沿用该加载器。CodeGuard 的 Rust [WasmGrammar](../crates/codeguard-runtime/src/wasm_grammar.rs) 已使用 Tree-sitter `WasmStore` 加载**同一固定字节**并在测试中解析 Java、Python、TypeScript、TSX。这里复用的是 grammar 资产，不是 JavaScript 加载器；Node 仅负责 npm 命令转发。Rust 加载成功只证明该加载路径的有限兼容性，不证明语法判定准确，也不代表 OpenSpec 14.2 的全部验收完成。

完整 WASM 发行仍须固定补丁、兼容范围及语料，不得复制活动目录或运行时取 latest。包内资产应离线可用，按需加载；取消或部分覆盖不缓存 clean。升级/回滚重新核验资产和缓存身份，保留历史观察与白名单失效记录。完整生产声明还需平台、宿主、原生工具和质量评测分别验收。

回滚不得静默回到旧 Python fail-open。只能恢复兼容严格契约的已验证版本；只能使用 legacy 观察时，交付继续未认证。
