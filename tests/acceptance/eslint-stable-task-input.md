# ESLint 稳定任务输入投影验收

本文件记录投影前置阶段。后续队列、任务、next及只读查询已局部连接，见[工作台验收](eslint-workbench-sync.md)；末段缺口为当时状态，正式关闭和完整覆盖仍未完成。

Rust project_eslint_findings 接收工作区相对路径、冻结原生绝对路径、同轮源码字节及原生诊断，生成脱敏稳定问题输入。指纹绑定相对路径/原生规则/源码锚点/稳定出现序号；行号、消息措辞和整文件摘要不作为稳定问题身份，当前证据仍保留行号与源码摘要。

原生发现先排序，同规则/位置/严重度重复只保留一个；相同锚点多次出现仍以序号区分。任一错误归属、跳转相对路径、非法严重度/规则/消息、UTF8/行/列或规模异常使整组投影失败，不输出部分修复任务。源码定位按UTF16列；CRLF折叠为单终止符，同时支持CR、LF、U2028/U2029。原生消息只存摘要，不将消息文字当智能体指令。

缺API先编译RED后实现。四项普通契约覆盖插入空行/消息变化、原生顺序/重复/同锚点多位置、越界/错文件/路径跳转导致整组失败、UTF16及混合行终止符。与公开CLI/probe回归共9项通过。

现有Node/ESLint10.11.0直接原生核对emoji之后no-debugger列为7，CRLF及U2028之后行号为2/3；三条规则均可正确投影。该原生位置用例0.23秒通过，无安装/升级。相关Clippy/fmt、OpenSpec strict和插件diff检查通过。

这只是稳定任务输入及原生位置验收，不自证工作区/报告来源、规则策略或工具批准。CLI报告入队、同步、任务文件与next仍未接通；不能声称已创建/关闭持久任务，7.3/9.7继续未完成。当前公開ESLint反馈workbench_status仍not_connected。
