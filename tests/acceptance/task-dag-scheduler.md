# 任务 DAG 与资源互斥局部验收（2026-09-25）

Rust core 的 `TaskGraph` 在执行前拒绝重复任务、未知/重复/自依赖、依赖环与重复或空资源。runtime 的 `run_task_graph` 在并发上限内执行已校验任务：同一资源 ID 不重叠；某任务失败、超时、取消或 panic 后，依赖项标为未完成，独立任务仍继续；排队期间取消或超过总截止时间时不启动新任务。执行回调取得同一绝对截止时间和取消标记，必须把它们传入 `run_process` 等受控执行接口。任意不响应截止时间的 Rust 回调无法由线程调度器强制抢占。

`crates/codeguard-runtime/tests/task_scheduler_contract.rs` 的六项测试覆盖坏图/非法并行度执行前拒绝、失败依赖与独立任务、同一构建资源互斥并证实其它资源可重叠、反向 ID 顺序的传递失败、排队取消、启动前截止时间和回调 panic。测试先因接口缺失失败，实现在 core/runtime 后通过。

这尚不是完整的 OpenSpec 3.4：正式 CheckPlan 与义务账本没有调用调度器，资源 ID 的构建根规范化、跨进程共享构建目录锁、取消后的真实原生进程树以及 Windows 平台整体联调仍须验收。不能把此局部调度测试解释为完整检查或交付通过。
