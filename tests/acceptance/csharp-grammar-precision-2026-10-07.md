# C# Grammar 精度验证记录

> 日期：2026-10-07；OpenSpec 8.4 / 14.19。
> 状态：**不满足 Wilson ≥ 0.98 门槛**，记录真实局限性。

## 验证结果

| 指标 | 值 |
|---|---|
| 总样本 | 500（200 合法 + 500 违规） |
| TP（真阳性） | 60 |
| FP（假阳性） | **0** |
| FN（假阴性） | 440 |
| TN（真阴性） | 200 |
| Wilson 下界 (95%) | **0.9398** |
| 门槛 | ≥ 0.98 |
| 结果 | **FAIL** |

## 分析

C# grammar（tree-sitter-csharp）的语法解析**检出率较低**（12%）：

- **已检出**（TP=60）：部分语法错误（如缺少括号）
- **未检出**（FN=440）：大部分语法错误（缺少分号、错误关键字、类型错误等）

**零假阳性（FP=0）**：grammar 不会将合法代码误判为违规。

## 局限性原因

1. **tree-sitter 的语法解析边界**：tree-sitter 是语法解析器，不做类型检查
2. **C# 语法复杂性**：C# 的语法比 Java/Python 更复杂，grammar 覆盖度有限
3. **语义级错误**：类型不匹配、关键字错误等语义级错误不在 grammar 检测范围

## 与其他语言对比

|---|---|---|---|---|
| Java | 250 | 0 | 0.9849 | ✅ PASS |
| Python | 240 | 0 | 0.9842 | ✅ PASS |
| Rust | 270 | 0 | 0.9860 | ✅ PASS |
| TypeScript | 270 | 0 | 0.9860 | ✅ PASS |
| JavaScript | 270 | 0 | 0.9860 | ✅ PASS |
| **C#** | **60** | **0** | **0.9398** | ❌ FAIL |

## 结论

C# grammar 的精度**不满足 Wilson ≥ 0.98 门槛**。
零假阳性表明 grammar 不会误判，但检出率低意味着漏检较多。

**建议**：
1. C# 语法检查应依赖原生工具（如 Roslyn）而非 WASM grammar
2. WASM grammar 可作为初检，但不能作为主要检查手段
3. 需要 C# 原生工具集成才能达到生产资格
