# Python原生语法探针的两次调用身份连续性

对应OpenSpec3.7、5.2、14.17及14.11的原生证据前置条件，父任务仍未完成。

发现：Rust隔离Ruff探针在版本探测后直接调用原路径做语法检查，只在检查结束才复核入口字节。版本命令若替换自身，旧实现实际启动了新制品，最终虽然未完成，但已执行非冻结入口。TDD反例实际触发第二个脚本的执行标记，测试失败；不能把最终撤回结果当作调用前身份保护。

修复：版本探测返回后、第二次语法调用之前，同时核验请求路径仍解析为原规范化入口及当前制品摘要与冻结字节相同；任一改变返回 `python_syntax_tool_changed`，不启动第二次调用。检查结束后复用同一核验，撤回字节或入口关系变化后的结果。无新报告版本，不改变原生优先、规则/配置范围、语法资格或可信关闭权限。

两项控制反例覆盖版本命令直接替换文件，以及版本命令把请求符号链接改指其它入口；均保留incomplete、无诊断和既有具体原因，第二次程序没有执行标记。已有机器报告反例继续拒绝F401/E902、错文件/位置、非error严重性与退出矛盾。

已有本机Ruff0.16.8另显式执行三类冻结输入：合法赋值completed；缺函数体和错误缩进diagnostics_observed；工具摘要前后相同、目标仍py312、版本仍ruff0.16.8。此处仅证明探针连续性与原生语法反馈，不证明项目配置、其它版本、独立holdout、原生任务关闭或完整交付。开发测试脚本不进入产品检查实现。

能力缺口：`TaskResolutionChecker`尚无Python；受保护服务固定要求identity.checker_id为syntax.native_confirmation，而Python稳定任务为python.ruff；原始报告读取仅支持syntax-confirm前缀和已有语法版本，不能核验python-syntax原始报告或Python通用0.7。不得通过改写任务身份、跳过首次消费收据或把本轮零诊断转换为已批准关闭绕过这些差距。

后续关闭接线须同时支持已批准的Python任务身份、两类首次报告及原反例冻结来源，明确原生目标版本与项目/批准上下文一致；对原反例与当前源码复检，保留失败、误报候选、父链及复发。项目文件不提供信任密钥或自签许可，py312开发差分的成功不能为其它项目版本发关闭证据。既有14.11验收标准和完整目标保留。

验证收口：探针单元3通过/1忽略；受影响原生差分协议目标4通过/1忽略；已有Ruff真实探针另显式1通过，三输入共6.01秒。首次漏加wasm-precheck的过滤调用实际0测试，不计验证；启用正确特性后RED明确执行替换制品的标记，修复后通过。默认/WASM workspace/all-targets严格Clippy、OpenSpec strict、差异空白及1582处本地文件链接检查通过；Erlang保护草稿摘要不变，历史报告/schema及发行锁不修改。CI既有Python探针目标会执行控制反例，真实工具忽略项仍需显式环境，不把本机原生测试描述为远端已完成。
