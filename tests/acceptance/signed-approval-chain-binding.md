# 多跳签名批准修订链（4.10 进行中）

`verify_and_bind_replacement_chain` 接受当前候选及从直接前驱到普通根决策的签名历史。每跳用宿主提供的公钥/最新撤销状态和受保护历史审核上下文核验 Ed25519、载荷范围、期限与快照原始字节；每个快照内部修订也必须匹配签名修订。工作区必须一致，序号严格递减，签发/审核时间不能越过后续签发时刻；旧候选还必须在受保护审核时刻有效。历史审核时间不能从项目自造字段推断。

旧条目在今天过期不会抹去合法历史：前序签名与候选按其历史审核时刻核验；当前候选仍按本次当前时钟核验。宿主须刷新前序公钥撤销状态，历史密钥被撤销时当前合法签名也不能覆盖它。

所有历史 pin 只由逐跳签名核验推导，接口不接收项目自选摘要。随后沿用既有严格替代链绑定：同一稳定 finding/规则/目标、逐跳撤销、候选字节、无环、无缺跳或多余节点。最多 32 个前序输入；超限在验签前拒绝。输出仍是非授权绑定结果，不能关闭任务或签发交付。

RED 为签名链 API 缺失；首次测试另发现乱序返回明确错误时断言错误地 unwrap，已修正为拒绝成功绑定的判定。三项测试验证三修订有效链、历史批准已过当前有效期但当时合法、链截断/乱序、前序私钥不符、序号回滚、未来签发、跨工作区、缺可信历史时间、历史候选未生效、多余节点、历史公钥撤销、空链与超 32 跳。单快照签名四项、旧精确快照十五项及依赖边界三项一同回归。

剩余：受保护公钥/历史时刻/最小序号来源与持久状态、代码基线 Git 祖先关系、真实发布原子性、可信宿主 CLI/MCP/Hook 接入及实际门禁。不提供项目自选上下文或私钥的 CLI，4.10 不勾选。

另补第四项反例：前序签名在所给历史时刻有效，但其审核发生于替代批准签发之后，明确返回 approval_revision_order_invalid，不能用签名有效替代修订时序检查。最终四项链测试、fmt 与全目标 Clippy 通过；该反例在已启动的全工作区回归之外单独执行。
