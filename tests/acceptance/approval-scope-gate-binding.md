# 白名单批准范围到最终门禁的绑定

状态：领域模型与签名预览接线，未接入可信宿主或真实批准发布。

## 验收行为

- `ApprovalScope` 保存工作区和当前批准上下文的完整非零小写 SHA-1/SHA-256 基线。
- `DeliveryInput.approval_scope` 由宿主独立冻结；`AllowlistDisposition.approval_scope` 来自已核验批准范围。不能从处置反向生成宿主信任。
- 最终门禁只有在双方范围存在、有效且相等时才能应用白名单，其余身份、策略、期限、原生覆盖与独立批准约束仍然生效。
- 签名预览携带原验签上下文范围，独立批准标记仍为 false。
- 跨工作区、不同基线、缺失范围、双方同填非法基线/工作区均不能处置发现。原始与活动阻断保留。
- 旧 JSON 缺范围仍可读，带白名单时返回 incomplete。没有白名单时正常 allow/deny 判定不依赖该字段。

## 测试证据边界

新增门禁用例首先因缺少 ApprovalScope 和两个范围字段编译失败；实现后验证精确 SHA-1/SHA-256 正例，以及跨范围、全零/大写/短摘要/HEAD、空或含换行的工作区、缺字段反例。签名预览契约验证范围未丢失。门禁用例属于合成领域输入，不能证明来源可信；签名链回归含本地实际 Git，但也不构成受保护宿主批准证明。
