# npm任务原工具复检

Unix `task verify ID WORKSPACE` 识别 `node.npm.audit` 稳定完整性任务。调用者显式提供 Node/npm入口、版本、原用户与全局配置及可选 registry；任务结构中的构建根选择原生 cwd，父工作区负责预算、报告与任务归属。任务Markdown不作为命令输入。

复用同一输入摘要/版本/锁节点审计服务，不先绕过租约保存。原生观察完成后，在任务验证锁内重新核验清单与锁，保存现有严格npm工作台报告、同步并附加 `verification_observed` 事件；关联现有 ready-to-verify 尝试。候选变化或租约错配不能授权复检写入。事件的 `state_after` 固定 open。

原生局部审计一致时仍 `still_blocked`，因为漏洞库覆盖及时效、可信策略尚未证明；原生失败为 incomplete，不转换成源码漏洞或误报白名单。对话反馈保留脱敏 advisory/解析版本、诊断与下一步。next及尝试历史读取器识别npm时间序列与报告；输入变化后不沿用旧结果，要求再次复检。

验收包括父工作区两根稳定任务、预算继承、零发现仍阻塞、带租约的真实尝试与受控原生失败、失败尝试不再等候尚未执行的复检，以及清单变化后旧复检失效。真实既有 Node 24.18.0/npm 11.16.0 的公开扫描加 task verify 通过，43.44秒；空锁离线结果不是可信漏洞覆盖证明，没有安装或执行包脚本。

正式任务关闭/重开、完整advisory归属、可信工具/配置/模块闭包、漏洞库时效与覆盖、自动check all及宿主完整交付门禁仍未完成。当前测试不得支撑所有npm依赖或所有平台已验收的结论。
