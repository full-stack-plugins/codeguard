# ESLint 显式目录逐文件检查验收

公开 lint typescript PATH 接受目录；仍需显式 Node/ESLint 入口、版本、原配置与cwd。Rust有界枚举JS/TS八种源码扩展名，按排序逐文件复用既有原生probe、报告同步和稳定任务，所有调用共享同一截止时间。目录协议0.1单独保留每文件相对路径及局部反馈、跳过项、未执行清单，并核对源码清单和显式工具/主配置字节前后变化。它不自动选择monorepo子配置，不声称完整项目或可信策略覆盖。

点条目、node_modules及符号链接分别显示未选择原因，不跟随链接；codeguard目录中的用户JS源码照常检查。条目/源码数量和深度有界；枚举或输入异常未完成，单文件失败保留其它文件发现。工作台未保存/同步成功也不能把目录标普通局部一致。取消/超时保留中断原因和未执行范围，空源码范围不当干净项目。

目录入口缺失反例先RED。受控CLI检查两个子目录同名app.js、codeguard/user/custom.js及原eslint.config.cjs，重复扫描首次新增4张稳定任务、第二次0张；一个文件退出2不覆盖其它发现，符号链接列为跳过；共同100ms预算留下3个未执行文件；工作区画像缺失返回工作台未完成。配置源码还暴露了原输入冲突/同步重复路径限制，已只允许配置与源码共享同一只读摘要，重复源码、其它输入别名和报告覆盖仍拒绝。

既有Node24.18.0/ESLint10.11.0真实公开目录检查62.34秒通过：违规JS、干净JS和原配置源码三个文件分别反馈，规则no-debugger保留，配置源码没有被排除。没有安装升级或批准门禁。48项相关普通回归通过；目标Clippy -D warnings、fmt及OpenSpec严格校验结果见本轮verification。当前公开目录JSON也通过Draft202012 schema实测，schema产物使用受控协议夹具，不冒充原生ESLint证据。

该进展是显式单配置目录调度。完整原生源集/ignore与monorepo配置归属、TS parser/tsconfig、插件导入闭包、依赖/CVE、正式关闭重开、原生完整证据与宿主门禁仍缺，7.3/9.7不勾选。

后续目录反馈升级0.2，支持显式子项目配置/cwd映射并保留选择来源，历史0.1 schema继续接受。当前实现与新增真实多项目样本见eslint-config-map.md；自动配置归属和完整覆盖仍未完成。
