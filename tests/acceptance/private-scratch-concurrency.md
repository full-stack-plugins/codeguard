# 并发私有工作区局部验收（2026-09-29）

`check all` 可以并发运行多个原生节点。旧 `DoctorScratch::create` 只将调用者传入的标签作为目录名；Python CVE 调用者以 PID 和时钟纳秒构造标签。并发任务若落在同一时钟刻度，一个任务独占创建后，另一个会报 `python_private_workspace_unavailable`，尽管项目及原生工具均可用。实际重复测试还观察到多根检查的该错误；这属于执行环境不完整，不能当作源码违规或通过。

先加入同标签 8 线程创建测试，旧实现 7 个线程因目录已存在而失败。现共享创建器为每次创建附加进程 ID 和进程内原子序号，保持 `0700`、独占创建、退出清理和不复用残留的语义。测试确认 8 个目录均不同、权限为 `0700`、释放后全部消失。所有使用该创建器的原生探针均得到同一并发唯一性保证；此测试不证明各原生工具本身的完整覆盖。

真实 CLI 回归：Python CVE 两构建根检查连续 20 次通过；完整 `python_cve_cli` 11 项串行运行连续 15 次通过。此前完整回归曾在输出上限测试出现另一个偶发终止原因，本轮未再次复现；不能仅据这些通过声称该问题根因已经消除。后续仍需独立审计进程输出超限的终止分类、正式 CheckPlan 资源锁和跨平台临时区行为。
