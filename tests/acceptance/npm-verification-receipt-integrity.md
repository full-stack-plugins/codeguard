# npm复检收据的归属与过期分流

本地报告、验证事件和消费收据都不是可信授权源。即使三个文件被一并改写摘要，next和尝试历史仍须核验复检本身的结构及任务归属，不签发交付通过。

本轮变更：

- 两个消费者读取npm报告原字节时拒绝递归重复JSON键。
- npm同步解析先核验全部静态结构、固定权威/覆盖状态、摘要格式及有界advisory/node字段，再核对当前清单/锁字节及锁节点归属；节点解析重读的锁字节也核对摘要。
- 验证读取器区分报告损坏与输入已变/不可读。仅结构有效且输入过期的报告失效后允许再次复检；报告损坏不能被默认为“历史过期”。
- 校验使用当前初始化工作区身份。任何复检结果，包括incomplete，都必须对应原任务的检查器、稳定完整性义务和构建根；另一个根的失败报告不能确认本任务尝试已复检。

`npm_workspace_scope_cli` 验证两种当前输入状态下的五类篡改：覆盖true、组件计数不符、重复authority、错工作区、错构建根。测试同时更新本地报告、验证事件与消费收据摘要；每个反例仍返回verification_event_invalid，原任务不关闭。合法旧输入失效仍能得到同一任务与新的复检指引。

构建根错配反例先观察到local_task_selected及旧incomplete尝试被接受，再补充精确任务匹配。这是局部收据及消费者验收；未证明受保护工具/配置/审计源身份、完整依赖图或漏洞库覆盖，也不是批准或正式关闭能力。

验证结果：49项不同普通回归通过，10项需指定原生Ruff用例本轮未运行。真实Node/npm公开扫描与task verify通过（45.05秒）；Clippy（-D warnings）、fmt、OpenSpec严格校验及diff检查通过。
