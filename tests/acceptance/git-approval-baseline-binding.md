# 签名批准的代码基线关系（4.5/4.10 进行中）

runtime 的 observe_git_ancestry 用宿主明确指定的 Git 绝对路径、仓库根、共同截止时间和取消标记执行原生命令。输入仅接受同格式完整非零 SHA-1/SHA-256；先检查完整历史，再核对两端为 commit，最后解释 merge-base --is-ancestor 的 0/1。其它退出、诊断、报告噪音、缺对象、非提交或浅历史均返回错误，不充当关系证明。同一提交可作为祖先。

argv 不经过 Shell，环境清空并重建；禁用 replace、graft、commit-graph 加速、按需取对象及可选锁。硬性 --no-lazy-fetch 不被旧 Git 支持时拒绝，不删除参数重试。系统/用户 Git 配置不进入调用，仓库配置仍存在，因此工具批准、仓库可信来源和只读隔离仍由宿主负责；不能声称本地路径已拥有不可绕过的权威。

CLI 库入口 verify_and_bind_replacement_chain_with_git 先完成签名/严格替代链绑定，随后从当前基线到根批准逐跳核对前序基线属于子基线历史。所有 Git 调用共享宿主预算和取消标记；无关关系返回 approval_baseline_not_ancestor，未完成沿用具体 Git 错误。原有纯签名 API 保留给没有 Git 观察的用途，不能用其成功值代替完整宿主入口。这里没有新增项目可选的 --approved/--git-trusted 参数，不签发最终门禁。

两次 RED 分别为原生祖先观察 API 缺失、签名链联合入口缺失。真实本机 Git 2.54.0 用例覆盖 SHA-1/SHA-256、正常/同提交/反向/无关关系、tree/零/短引用/缺对象拒绝、replace/graft 伪造、浅历史、缺工具、取消与超预算，观察前后 config/index 字节不变。部分克隆反例以本地假传输记录是否启动，无外部服务或网络凭据；普通原生命令作正对照，Codeguard 观察不得启动该传输。联合签名用例验证真实三提交批准链、签名有效但无关基线与浅历史。

原生祖先四项和签名链五项专项通过，单快照四项、旧快照十五项、依赖边界三项回归通过；完整工作区终态另记。剩余为受保护公钥、历史审核时刻、最低序号与仓库/工具来源，真实策略发布及宿主 CLI/MCP/Hook 门禁接线。本机原生观察不认证全部平台或独立批准流程，4.5/4.10 不勾选。

追加 RED 发现普通签名入口仍接受全零代码基线。现 Rust 宿主上下文与 signed-approval-payload schema 均拒绝 SHA-1/SHA-256 的零 ID，避免在没有 Git 联合入口时把空基线视为有效批准范围。单快照测试增至五项，签名链另覆盖上层取消标记；两组五项、旧快照十五项及边界三项通过。六个结构样本验证有效完整 ID、两种零 ID、大小写与短引用；schema 校验不证明签名有效。此后补充在已经启动的全量回归之外单独验证。

完整工作区离线回归最终退出 0；后补调整另经最终专项、Clippy 与 fmt 验证。默认忽略的原生工具用例不计执行；受保护宿主来源、发布与门禁仍未完成。
