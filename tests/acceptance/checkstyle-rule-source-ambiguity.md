# Checkstyle 原生规则身份歧义

对应 OpenSpec 6.3 和后续精确白名单身份绑定。10.21.4 有自定义模块 ID 时原生 source 只有该 ID，两个不同检查模块共用 ID 会无法从单条诊断区分类别。无自定义 ID 的同一检查器重复声明也会共用同一个 source。原配置识别先接受共享 ID，新增反例复现断言失败。

现在静态局部执行识别要求模块属性名唯一、每个检查实例的原生 source 可区分。默认来源按当前锁定版本的内置检查类核对；自定义 ID 原样比较。同检查类的不同 ID 可接受；共享 ID、重复默认来源或重复 severity/id 属性进入上下文待解析，不改变用户配置，不制造源码违规，也不默认选先出现或最后出现的属性。

真实正式 CLI 追加三种场景：既有单检查器原生诊断、共享 ID 的两个模块返回 configuration_context_unresolved/零活动 finding、改为不同 ID 后原工具显示类型及参数/返回共三条诊断。仍退出 3，交付未评估。共享 ID 的拒绝是配置身份歧义，不声称 Checkstyle 自身不支持该配置。

这不是白名单生效证明；完整原生配置模型、ID 与批准规则/义务映射、稳定任务身份、白名单及门禁仍须接线，6.3 不勾选。
