# 批准签名与快照绑定（4.5/4.8 进行中）

Rust runtime 使用固定 ring 0.17.14 的 Ed25519 实现，未自行实现密码算法；依赖从已有 Cargo 缓存离线解析。没有签发 CLI、内置测试公钥或项目自选信任库入口。公钥、撤销状态、可信时间、最低修订序号、工作区与受保护基线由宿主预先固定；当前仅提供领域应用 API，受保护宿主加载尚未接通。

签名封装 1.0 包含 key_id、approval_json 原始 UTF-8 字符串和小写十六进制 64 字节签名。签名消息为 ASCII `codeguard.approval.v1`、NUL、精确 key_id、NUL、原始 approval_json 字节。核验不能重新序列化 JSON；空白变动也必须重签。载荷绑定工作区、策略修订、Git SHA-1/SHA-256 基线、修订序号、签发/到期时间和批准快照原始 SHA-256。封装最多 16 KiB、载荷最多 8 KiB、快照最多 128 KiB；重复已知字段、未知字段或协议版本拒绝。

公钥必须当前有效且未撤销；签发时间不能未来或早于密钥生效，批准不得超出密钥期限、宿主最长期限或最低修订序号。工作区、修订和基线必须逐字一致。缺可信时钟不能授权。`verify_and_bind_candidate` 在签名核对后仍严格解析快照，核对签名修订与快照内修订，再以签名得到的摘要走原精确候选绑定；候选原始字节变化不能靠本地 approved 文本放行。替代候选在此普通绑定中继续拒绝，须后续核验每跳签名修订链。

测试先 RED：核验 API 缺失；另一个 RED 为签名与快照桥接入口缺失。GREEN 四项覆盖有效签名、换工作区/修订/基线/快照、换私钥、改被签原文空白、错签名域、撤销/密钥失效/未来、批准过期/未来、无时钟、回滚/超长期限、重复 JSON 字段、额外 approved、坏协议/长度/零签名、签名与快照修订错配及自改候选字节。原有批准快照十五项继续通过。

这些测试仅验证给定宿主输入下的密码学绑定；固定 seed 是测试密钥，不是发行信任锚。VerifiedApprovalSnapshot 不签发门禁，不证明快照协议或原生覆盖；签名成功不能覆盖原生工具失败或原生身份缺失。受保护密钥来源/轮换/撤销持久化、可信时钟与防回滚状态、当前 PR 基线获取、完整签名修订链、CLI/MCP/Hook 接入及真实放行仍缺，4.5/4.8 不勾选。同权限本地调用者能替换输入公钥时，不能获得不可绕过保证。

分层验收曾发现 CLI 直接生产依赖 ring 违反现有边界，完整回归因此终态失败。已将密码学原语移至 runtime，仅允许 CLI dev 依赖 ring 用于测试签名；CLI 的 normal/build 边及 core 的 ring 边仍禁止。新增边界反例保持别名/目标条件不绕过生产边界。原语不解析策略或加载信任库；协议与宿主上下文仍在 CLI 应用服务，纯 core 不依赖密码库。

独立原语验收使用 [RFC 8032 §7.1 TEST 1](https://www.rfc-editor.org/rfc/rfc8032.html#section-7.1) 的空消息公钥/签名向量；不引入向量私钥。runtime 两项覆盖标准向量有效、改消息/签名、零公钥/签名和超 9 KiB 消息拒绝，均通过。完整工作区启动后新增的原语测试另行执行，未冒充默认未运行的用例。
