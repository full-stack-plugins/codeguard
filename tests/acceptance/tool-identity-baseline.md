# 工具制品身份局部验收（2026-09-24）

`tool_identity` 从已解析的 `LockedTool` 出发，对 system 绝对路径、项目 wrapper、受管缓存三类 origin 分别解析真实普通文件，并核对 SHA-256 与基础可执行位。项目 wrapper 和受管缓存拒绝绝对/父目录路径及越出各自根目录的符号链接；运行时单独核对锁定摘要。工具锁可声明 `bundle` 目录树摘要：按路径和内容确定性计算，拒绝特殊文件、符号链接、超限和任何委托文件变化。缺失、摘要不符、不可执行和运行时缺失均返回显式 issue。Rust 单元测试覆盖三类来源、路径穿越、越界链接、内容篡改、不可执行文件、运行时变化及委托 jar 篡改。

这是**静态制品匹配**，不是来源批准、启动成功或规则加载证明。`MavenProbeRequest::from_locked_artifacts` 要求 Maven 入口、JDK 二进制、`JAVA_HOME/bin/java` 和 bundle 树均匹配才构造探测请求；执行前、版本探测后及 validate 后重复核对这些身份。测试让原生命令在 validate 阶段改写 JDK 入口或委托 jar，即使退出码为 0，结果仍为 incomplete。真实 Maven 3.9.16/JDK 26.0.1 的 POM 4.1 反例通过了入口与 `libexec` 整树核对后的调用链。该锁由测试现场生成，仅验证机制，不是可信发行签发；JDK 动态依赖、项目扩展及本地依赖仓库仍可能进入执行闭包。`tools verify` 的可信锁来源、完整依赖闭包、项目诊断和恢复动作仍属 OpenSpec 5.2/5.6，不能把本局部验收计作完成。
