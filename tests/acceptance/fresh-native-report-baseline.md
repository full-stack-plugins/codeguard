# 原生文件报告的新鲜度局部验收（2026-09-24）

`codeguard-runtime` 的 `prepare_fresh_report` 只接受预先创建、当前用户拥有且不对其他用户开放的绝对目录；逐级拒绝符号链接。它在启动前用目录文件描述符确认报告目标不存在，不会删除或覆盖旧报告。完成后只通过同一个目录文件描述符读取普通文件，拒绝缺失、符号链接、多硬链接、特殊文件及超限字节。

`run_process_recorded_with_report` 按“报告预检 → 受控原生进程 → 私有原始日志 → 报告读取 → 共同截止时间复核”执行。旧报告会在 spawn 前拒绝；进程退出 0 但未生成报告不能成为成功；日志写入失败也不能返回完整结果。进程非零且生成了报告时保留原生退出状态和报告字节，供适配器提取可信部分诊断并将检查判为未完成。

验收命令：`cargo test -p codeguard-runtime --test fresh_report_contract --offline`。该局部测试使用测试 shell 生成字节，并不代表官方 P3C、Maven 或其它扫描器的真实验收。应用层仍须把受控报告目录和原生命令输出参数绑定，复核源码、规则包、工具、扫描范围与报告内容；同一用户并发篡改运行目录的威胁边界仍需 S03/S11 隔离策略处理。故 OpenSpec 5.4 保持未完成。
